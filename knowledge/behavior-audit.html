What Moon+ Reader already offers, which improvements need testing, and what the retained evidence actually proves.

What is established

One retained interoperability failure

RUNTIME-PDF-PREV-001 / RT-16: two edited AcroForm outputs contain an incremental trailer with /Prev -1. pypdf 6.15.0 rejected both with ValueError('negative seek value -1'); PyMuPDF 1.28.0 opened with repair and recovered the edits. Moon reopened the files with the values visible.

The second repetition changed only the text field. Saving occurred when closing with Android Back, not through a separately verified Save command. This establishes malformed-output interoperability, not demonstrated loss of the field values.

Two concerns needing confirmation

AUX-STATUS-001: a one-page PDF once showed 101/1 after correctly finding and highlighting the requested text. The anomaly was not repeated; the successful search remains a successful search.

AUX-A11Y-001: some captured controls lacked UIAutomator labels. No TalkBack task established whether the controls were announced or usable. This is an accessibility-testing lead, not a reproduced TalkBack failure.

Evidence boundary: these observations are from 21 November 2026 on the supplied APK declaring 10.8 / 1008000, in an account-free Android 16/API 36 x86-64 emulator. The publisher of those bytes was not authenticated. They cannot establish a defect in the official Play release. No proprietary-code inspection was performed for this behavior-review expansion.

Make the tests decisive

Reviewers recommended 197 editorial or acceptance-test changes across 72 proposals, consolidated into 38 groups. These are review recommendations, not 197 software defects. The original proposal files have not been rewritten. MOON-056 and MOON-065 required no material correction in this review.

Common test contract

First establish a working supported route and independently validated synthetic input. Observe the failure at the actual boundary. Compare complete saved content, not only a success toast or count. Credit an existing fallback when it meets the requested outcome. Record setup failures, partial tests and unobservable branches separately. Never infer data loss when the original values remain recoverable.

EC-01 · Save and export failure

MOON-001, 002

Replace internal return-value assumptions with a proven failure at the real destination after a healthy control. Verify recoverable edits, truthful feedback, full output and safe replacement separately.

EC-02 · Sync retry and completion

MOON-003, 041

Test logical delivery through supported lifecycle/retry routes, without prescribing an outbox or button. Separate server commit, acknowledgement and receiver application; duplicate transport attempts are not duplicate notes.

EC-03 · Equal-size covers

MOON-004

Prove cover synchronization first. Measure the objects after import because images may be re-encoded. Distinguish failed transfer from correct bytes displayed through a stale cache.

EC-04 · Speech completeness and exclusions

MOON-005, 066

Measure the effective engine limit and compare the complete ordered text stream. Submission, audible output and cursor position are separate. Intentional excluded regions are not truncation.

EC-05 · Uncommitted drafts

MOON-006

Seed a committed note and a separate unconfirmed draft. Distinguish activity recreation, rotation and background process death. Explicit Discard and source export require independent checks.

EC-06 · Reflow and no-text pages

MOON-007–009

Use independent visual, tag and stream-order oracles. Test saved occurrence anchors separately from selection. A correct zero-match result on an image-only page is not an OCR defect.

EC-07 · Portable annotation geometry

MOON-010

Separate page crop, display crop, PDF rotation and device orientation. Record the initial saved mark and a declared tolerance so imprecise drawing is not mistaken for later drift.

EC-08 · Form interoperability

MOON-011

Preserve the one historical save-output failure. Test extra field types with new validated inputs; parser acceptance, visual appearance and value recovery are distinct outcomes.

EC-09 · Undo history

MOON-012

Define exact user transactions and document-switch/history lifetime. Editor undo differs from a committed annotation edit. Disabled Undo on a pristine document may be correct.

EC-10 · Rendering backend recovery

MOON-013

Establish two genuinely selectable paths before A/B testing. Allow supported close/reopen recovery; define fonts, geometry and selection oracles rather than requiring an assumed hot switch.

EC-11 · Night colors

MOON-014

Respect alternative outcomes: figure preservation or a page-original-color exception. Original RGB and preserved hue are different promises. Verify reversible comparison and unchanged source bytes.

EC-12 · View profiles and comics

MOON-015, 068

Define source page/image identities, crop precedence and LTR/RTL half order. Rotating to display both halves does not prove loss of the selected half; check again after returning.

EC-13 · Two-document isolation

MOON-016

Test independent edits under each pane's actual save model. Correct autosave may satisfy isolation without a new Save/Discard dialog.

EC-14 · Search semantics and cancellation

MOON-017–021

Declare literal/regex, case, direction and span oracles. Separate Unicode equivalence from accent folding. Test a bounded pending search and subsequent valid query, not private callback injection or pathological workloads.

EC-15 · Shelf search

MOON-022

Use content-only positives and metadata-only negatives. Replace the actual app-visible edition. Correct results or fast timing cannot prove the app avoided rescanning content.

EC-16 · Filtered annotation export

MOON-023

Define exact record identities, AND filters, selection scope and stable order. Compare exported text and book associations as well as counts.

EC-17 · Settings discovery

MOON-024

Find the manual control and exact-label route before testing aliases. An unpromised alias is not a regression; visual, keyboard and accessibility focus need separate observations.

EC-18 · Annotation interchange

MOON-025, 026, 028

Distinguish book, edition and annotation identity. Use a clean import target, exact Unicode policy and named consumer. Safe atomic rejection of malformed exports is not data loss.

EC-19 · Batch study exports

MOON-027

Specify selected annotations rather than complete-book conversion. Define CSV dialect, Markdown rendering and per-book versus combined transactions, including literal-safe spreadsheet handling.

EC-20 · Highlight and share delivery

MOON-029–031

Identify supported provider acknowledgements. Inspect receiver-visible MIME, bytes and URI lifetime. Compare full long-text content with explicit units and preserve an honest uncertain state after lost acknowledgement.

EC-21 · Export versus printing

MOON-032, 074

Visible markup does not prove editable export. Modal print preview can correctly prevent a race. Separate canceled dispatch from internal preview creation and normal autosave.

EC-22 · Citation backlinks

MOON-033

Credit existing relinking. Define physical, embedded and printed page labels separately. Use repeated quote occurrences and a controlled external receiver; do not invent a link scheme.

EC-23 · Whole-library restore

MOON-034

Inventory included and referenced assets. Prove clean restore before collision, cancellation and interruption tests. Preflight validation alone does not prove transaction safety.

EC-24 · EPUB styles and languages

MOON-035–038

Check publisher-formatting preview first. Declare relative layout, glyph, whitespace and language oracles. Separate doubled app text size from OS scaling and visual tables from assistive semantics.

EC-25 · Reading position

MOON-039, 043

Require the same visible source fragment rather than unchanged pagination. Local relayout and remote undo are separate. Existing history can satisfy recovery without a new control.

EC-26 · Footnote return

MOON-040

Use validated footnote markup, multiple reference occurrences and explicit return actions. Test keyboard and TalkBack focus separately; require the outcome, not a particular stack implementation.

EC-27 · Conflicting replicas

MOON-042

Start from a healthy common note. Reverse arrival order in independent trials. A resolved replica is no longer stale: use a separately held replica for resurrection tests.

EC-28 · Interrupted downloads

MOON-044

Interrupt a measured payload after a healthy control. Preserve the prior usable edition. Hidden staging and a safe full restart can satisfy integrity even without resumable downloads.

EC-29 · Identity and storage recovery

MOON-045, 048, 057

Credit documented relinking and the explained selected-file route. Distinguish provider outage, grant denial, missing source and imported copies; hidden shelf entries are not evidence of deleted notes.

EC-30 · Bulk catalog operations

MOON-046

Seed distinct prior values and a later unrelated edit before undo. A read-only book is not a fault in a catalog-only update. Report accurate partial completion or atomic rollback separately.

EC-31 · OPDS boundaries

MOON-047

Name actual protocol and authentication profiles. Separate discovery, download and opening. Fix MIME aliases and feed bytes before testing; incompatible authentication is not a regression.

EC-32 · Assistive and scaled UI

MOON-049–052

Establish working TalkBack, keyboard and Switch Access controls separately. Measure tasks, roles, focus and error announcements rather than XML alone; preserve escape routes and actual viewport/scaling values.

EC-33 · Narration and authored audio

MOON-053–055, 067

Prove audio and actual focus interruption. Voice availability is not interface-language coverage. Distinguish queued text from playback, and TTS from publication-authored media overlays.

EC-34 · Backup protection

MOON-058

Prove correct-secret restore before wrong-secret or tamper checks. Compression is not encryption; arbitrary damaged headers do not test authentication. Key rotation cannot revoke copies of old keys.

EC-35 · Performance and e-ink

MOON-059–061

Measure readable and interactive events, not the splash screen. Use a fixed-state memory series and whole-trend analysis. Emulator images cannot establish physical ghosting, refresh or energy.

EC-36 · Diagnostics and capability reporting

MOON-062–064

Use inert canaries and controlled receivers for draft/cancel tests. Separate support, evidence basis and test outcome. Do not invent release versions or call copied fixtures executed coverage.

EC-37 · Dictionary and translation

MOON-069, 070

Respect the actual provider contract. Handoff without a returned result is unknown. Use repeated text at distinct locations, prove controllable replies, and credit correct serialized scheduling.

EC-38 · Review, statistics and temporary sessions

MOON-071–073

Verify review restart after acknowledged answers. Define overlapping reading-time accounting and measurement precision. Offline silence cannot prove there is no queued history upload.

Execution priorities

  1. Establish the test environment. One operator owns the disposable emulator. Verify build identity, network restriction, fixture hashes and cleanup. Official-release attribution requires an authenticated official build.
  2. Complete EPUB and search foundations. RT-10 covers chapters, contents, font-size changes and reopening. RT-12/13 cover explicit search modes, malformed-query recovery, cancellation and the next successful action.
  3. Check durable edits and round trips. Complete annotation CRUD, rotated geometry, export/import, relinking and clean backup/restore before controlled failure tests.
  4. Exercise recovery. Confirm the fault reaches the selected destination; preserve original outputs. Open a healthy document after each benign malformed-input case.
  5. Provision dependent tests separately. Cloud needs controlled test accounts/backends; speech needs an identified engine and output oracle; accessibility needs actual assistive services. Missing prerequisites stay blocked.
  6. Measure quality rather than infer it. Keep raw timing trials and memory series. Use named hardware for physical-device and e-ink conclusions.

The separate runtime workflow remains pending for this snapshot. This report does not predict its installation, test or cleanup results. The 38 correction groups are available to guide execution without rewriting historical results.
